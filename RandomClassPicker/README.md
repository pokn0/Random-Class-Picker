# Random Class Picker（随机换职业）

点一下，用**真随机**从你已保存的套装里抽一个职业并直接切换过去。

- 随机数来自 **random.org**（大气噪声 / ANU 量子真空涨落，物理熵源，不是伪随机算法）
- 连不上或超额时默认**降级到本地伪随机**，并在界面上用颜色**明确标注**这次是真随机还是兜底
- 也可以设置成"只用真随机"，拿不到就直接报错，绝不偷偷用伪随机
- **生产和采集职业被永久排除**，代码层面写死，没有任何开关能把它们放进池子

> 环境：国服 XIVLauncherCN / Dalamud `15.0.3.5` / `DalamudApiLevel 15` / .NET 10。
> 全部代码已在本机编译通过（Debug + Release，0 error / 0 warning）。

---

## 1. 编译与加载

```powershell
cd $env:APPDATA\XIVLauncherCN\RandomClassPicker
dotnet build -c Debug
```

产物直接落到 `%APPDATA%\XIVLauncherCN\devPlugins\RandomClassPicker\`。

游戏内：`/xlplugins` → 开发者设置 → 勾选开发者模式 → 启用 **Random Class Picker**。
改完代码重新 `dotnet build` 后点一次 Reload 即可热重载。

## 2. 指令一览

| 指令 | 说明 |
| --- | --- |
| `/rcp` | 开关主窗口 |
| `/rcp roll` | 全职业池随机（受设置里的勾选与开关约束） |
| `/rcp tank` | **只在防护职业（坦克）中随机** |
| `/rcp healer` | **只在治疗职业中随机** |
| `/rcp melee` | **只在近战职业中随机** |
| `/rcp ranged` | **只在远程物理职业中随机** |
| `/rcp caster` | **只在远程魔法职业中随机** |
| `/rcp list` | 列出所有套装（含职能、是否勾选、是否在池中） |
| `/rcp status` | 打印当前筛选结果：每个职能"已勾选几个职业 / 有几个可用套装" |
| `/rcp daily` | 打开任务搜索器（随机每日任务面板就在它上面） |
| `/rcp roulette` | 列出全部随机任务（ID / 名称 / 完成状态 / 勾选状态），顺序与面板一致 |
| `/rcp debug` | 打印职业职能映射与套装快照（同时写入 `dalamud.log`） |
| `/rcp help` | 帮助 |

职能指令的别名：`坦克`/`t`、`治疗`/`heal`/`h`、`近战`/`m`、`远程`/`p`、`法系`/`c`。

当某个职能下没有可用套装时，指令会在**聊天栏给出明确原因**（没保存套装 / 职业没勾选 /
被"排除特殊职业"关掉了），不会静默失败。

### 抽签时的聊天输出
每次抽签都会输出本次的**池子范围**和该职业的**历史被抽中次数**：

```
[随机职业] 从6个职业（骑士，战士，暗黑骑士，绝枪战士，剑术师，斧术师）中抽取到了骑士，
该职业历史被抽中3次 —— 真随机·random.org
```

## 2.5 界面外快捷入口（服务器信息栏图标）

**不用打开窗口、也不用输指令**：插件会在界面顶端的**服务器信息栏（DTR）**放一个常驻图标。

- **左键点击** —— 立刻随机抽一个职业并切换（支持设置里的所有筛选规则）
- **按住 Ctrl 左键** —— 打开插件窗口
- 图标上会显示**最近抽中的职业名**（抽签过程中显示 `…`），悬停显示上次结果与该职业累计次数

可在「设置」标签页关闭该图标，或关闭其中的符号只显示职业名。

> **看不到图标怎么办**：DTR 不是可以随便漂浮的悬浮窗，它属于服务器信息栏。
> 需要在游戏里 `系统 → 界面设置 → HUD`，把服务器信息栏的那个条目从隐藏列表里启用，
> 或解锁 HUD 布局把它拖到可见位置。也可以在 Dalamud 设置里检查是否忽略过该条目。
>
> 另：`DtrInteractionEvent` 只提供修饰键、**拿不到鼠标按键**，所以"打开窗口"用的是
> Ctrl+左键，而不是右键。
>
> **注意 `ModifierKeys` 的枚举类型**：它是 `Dalamud.Game.Gui.Dtr.ClickModifierKeys`，
> **不是 `ImGuiKey`**。`Enum.HasFlag` 要求两边是同一个枚举类型，传错类型会在**运行时**
> 抛 `ArgumentException`，而编译期完全不报错（这个 bug 真出现过：表现为"点图标没反应"）。
> 另外不要用 `HasFlag(ClickModifierKeys.None)` 判断"没按修饰键"——零值按位与恒为 0，
> 对任何值都返回 true。本项目改用 `(int)keys != 0` 判断。

## 2.6 随机每日任务（任务搜索器面板）

打开游戏原生的**任务搜索器**（`/rcp daily` 或游戏里自己开），窗口右侧会叠加一个自绘面板：

- **每个每日随机任务一个复选框** —— 勾选的才进入随机池
- 每行右侧显示该任务的完成状态（`未完成` 绿色 / `已完成` 灰色）
- 底部 **`🎲 随机抽一个并排队`** 按钮：从"已勾选 **且** 未完成"的任务里随机抽一个，
  直接**发起参加申请**（等价于在任务搜索器里点该随机任务并确认排队）
- 面板上会显示当前队列状态与上次抽中的任务

抽选同样支持真随机源设置，聊天栏会输出本次池子范围：

```
[随机职业] 从8个未完成的随机任务（顶级迷宫，满级迷宫，练级迷宫，…）中抽取到了练级迷宫，
已发起参加申请 —— 真随机·random.org
```

默认勾选全部随机任务，**但会自动排除"导师随机任务"**——它有额外前置条件，自动排队只会失败。

### 列表内容与顺序的三条规则

1. **只显示作战随机任务。** 判据是游戏自己的字段 **`ContentRoulette.ContentType.RowId == 1`**
   （DailyDuty 用的也是这个）。**不要用名字前缀做判据**——第一版用「随机任务：」前缀过滤，
   虽然凑巧能滤掉"陆行鸟竞赛"，但那只是巧合。前缀白名单现在只作为兜底。
2. **顺序按游戏内任务搜索器的实际排列**，写在 `DutyRouletteCatalog.DisplayOrder` 里：

   ```
   顶级迷宫 → 满级迷宫 → 拾级迷宫 → 练级迷宫 → 讨伐歼灭战 → 主线任务 →
   行会令 → 团队任务 → 大型任务 → 指导者任务
   ```

   实测确认这个顺序 **既不等于 RowId 升序，也不等于 `ContentRoulette` 表的内部顺序**
   （顶级迷宫是 id 5 却排第一，拾级迷宫是 id 2 却排第三），所以只能显式指定。
   游戏内如果还有未列出的条目，会排在列表末尾（按 ID 顺序）。
3. **行会令（id 4）不参与随机**，写在 `ExcludedRouletteIds` 里——它虽然出现在同一个列表里，
   但内容性质与副本不同，按需求排除。条目会从面板上隐藏。

另外：**已完成的任务自动取消勾选**。这只发生在**显示层**：保存的用户偏好不变，
所以第二天重置后会自动重新勾上，不会因为"今天打完了"就永久丢失你的选择。
已完成的行会变灰且不可点击，行首标记为 `○`，未完成是绿色 `●`。

> 排查提示：`dalamud.log` 有 100 MiB 上限，**写满后就不再记录**（实测卡在 104858336 字节）。
> 所以排查这类数据问题时用 `/rcp roulette` 生成的
> `pluginConfigs\RandomClassPicker\roulette-diagnostic.txt`，它包含当前顺序、
> 保存的勾选原始数据、以及表内全部 `ContentType=1` 条目及其"在列表/已排除/被过滤"状态。

面板位置固定在任务搜索器窗口右侧。如果挡住内容，可在「设置」里关掉
「在任务搜索器窗口上显示面板」，改用 `/rcp daily` 只看状态。

### 面板显示不全怎么办

第一版面板宽度固定 240px 且从窗口右边缘往左算位置，在有详情栏的情况下会被挤出屏幕。
现在改成：

- **默认宽度 300px**，设置里有 `面板宽度` 滑块（200–600px）
- **默认贴在任务搜索器左侧**（避让右侧的副本详情栏）
- **位置做视口边界收敛**：无论怎么算都不会跑出屏幕
- **可选手动摆放**：设置里打开「面板位置手动摆放」后面板带标题栏、可以拖，位置会记住
- 完成状态改成行首的 `●`/`○` 标记（悬停显示文字），不再占用右侧空间

## 2.7 出海垂钓随机航线（申请航线菜单）

跟 NPC 对话打开**申请航线**菜单时，菜单旁会叠加一个自绘面板：

- **近海 / 远海逐条勾选**（线路由游戏动态给出，默认全选，取消哪条记哪条）
- 底部 **`🎲 随机抽一条并申请`** 按钮：从已勾选的航线里随机抽一条并**直接提交申请**
- 抽中结果会写在面板上并回显到聊天栏

### 为什么必须按菜单内容识别

申请航线用的不是专用窗口，而是**通用的 `SelectString` 文本选择菜单**——限定职业任务等
也用同一个窗口。所以不能只看窗口名，而是按菜单首行文本判定：

```csharp
var header = unit->GetTextNodeById(2);
if (!header->NodeText.ToString().Contains("要乘坐哪条航线")) return;   // 不是申请航线
```

选项文本从 `AtkValue` 里取（`AtkValueType.String == 8`，成员类型是 `CStringPointer`，
它自带 UTF-8 解码的 `ToString()`）：

```csharp
for (var i = 0; i < unit->AtkValuesCount; i++)
{
    var v = unit->AtkValues[i];
    if (v.Type != AtkValueType.String || v.String.Value == null) continue;
    // 按出现顺序编号 = 菜单索引
}
```

提交选择：

```csharp
var values = stackalloc AtkValue[2];
values[0].Type = AtkValueType.Int; values[0].Int = -1;   // -1 = 由索引选择
values[1].Type = AtkValueType.Int; values[1].Int = menuIndex;
unit->FireCallback(2u, values, true);
```

> **待实机确认**：`FireCallback` 的参数形式（2 个参数、第 2 个为 -1）是按 ATK 回调惯例写的，
> 我无法在沙箱里实机验证。如果点了按钮没反应，把面板上的失败提示或日志发我。

## 3. 界面（五个标签页：抽签 / 设置 / 职业池 / 套装·历史 / 抽中统计）

### 抽签
当前职业+等级+职能、已保存套装数、**当前设置下的可用候选数**；一个大按钮做全职业随机；
下面一排**按职能抽签按钮，每个按钮上带该职能的可用套装数**（为 0 时按钮自动禁用，
鼠标悬停可看到对应指令）；抽签结果区显示职业/职能/套装/品级/候选数，以及本次是真随机还是兜底。

### 设置
- **随机数来源**：random.org 真随机（失败降级）／只用真随机（失败报错）／只用本地伪随机
- **测试 random.org 连接**按钮：立刻发真实请求验证网络
- **排除特殊职业（青魔法师、驯兽师）** 开关 —— 特殊职业 = 限定职业（Limited Job）
- 抽到当前职业就重抽 / 只抽满级（品级 100）套装
- **同职业只取品级最高的套装**（默认开启，避免抽到装备缺件的旧套装）
- 抽完立即切换 / 结果打印到聊天栏
- **界面外快捷入口**：服务器信息栏图标开关、是否显示符号
- **随机每日任务**：任务搜索器叠加面板开关、「打开任务搜索器」按钮

### 职业池
- 顶部显示"已勾选 N / M"，只有**打勾的职业才进入随机池**
- 快捷按钮：全选战斗职业 / 全部取消 / 取消所有特殊职业
- **按职能批量勾选**：每个职能一个按钮，显示"该职能已勾选数/总数"，点击即全选或全不选
  （悬停显示对应指令）
- 下方按职能分组逐个职业勾选，**特殊职业单独一组**并提示"排除特殊职业"开关当前状态

### 套装 / 历史
每个套装显示职业（职能）、品级、是否当前，以及**是否在池中（●/○）**；下方是最近 20 条抽取记录。

### 抽中统计
一张表格列出**每个职业被抽中的次数**、占累计抽签的百分比、以及当前是否在池中（不在池的会说明
原因：未勾选 / 被特殊职业开关排除 / 无可用套装）。默认按次数降序排列。附带：

- `重置统计`：清零计数
- `复制统计到聊天栏`：把统计打印到聊天栏
- `只看抽中过的职业`：过滤掉次数为 0 的行

统计写入配置文件（`DrawCounts` / `TotalDraws`），**跨游戏重启长期保留**。

## 4. 筛选链路（为什么某个职业抽不到）

候选池按固定顺序逐层过滤，任一层不过就不进池：

1. **生产/采集职业** —— 永久排除（代码写死）
2. **职业白名单** —— 只保留「职业池」标签页里打勾的职业
3. **排除特殊职业** —— 开关开启时排除青魔法师、驯兽师
4. **职能限定** —— 由 `/rcp tank` 这类指令带入
5. **只抽满级套装** —— 可选
6. **同职业取品级最高的套装** —— 可选（默认开启）
7. **抽到当前套装就重抽** —— 可选（只排除身上那一套；不影响界面显示的"可用数量"）

排查问题用 `/rcp status`。注意界面上的"可用数量"**不**包含第 7 条的效果。

## 4.5 资源占用评估（长时间使用会不会变大？）

结论：**不会无限增长，且占用极小。**

| 数据 | 上限 | 体积 |
| --- | --- | --- |
| `DrawCounts`（抽中统计） | 最多 43 个职业键 | ~1.5 KB，有界 |
| `TotalDraws` | 一个整数 | 几字节 |
| `History` | 代码写死上限 20 条 | ~1.3 KB，有界 |
| `EnabledJobIds` | 最多 43 项 | ~0.3 KB，有界 |

**配置文件稳定在 3~4 KB，抽一万次也一样**；内存里这些集合的元素个数同样有上限。
唯一随时间增长的是 `TotalDraws` 的**数值**（不是体积）。

不过做这次评估时顺手查出了两个**与统计无关**的真实开销，已修复：

1. **每次抽签写两遍配置**：`RecordDraw` 与 `AddHistory` 后各存一次，同一份 JSON 被完整
   序列化并落盘两次。现在只落盘一次。
2. **界面每帧重复建池约 10 次**，每次都被每个套装配一个解码后的字符串。现在：
   - 筛选阶段改用"不解码名字"的 `EnumerateRawGearsets`，**只对最终进池的少数几个套装解码**
   - `AllRoleStats()` 一次算出全部职能，取代 5 个按钮各建一次池
   - 缺失职业清单按帧缓存
   - 槽位扫描结果按"当前套装索引"失效缓存
   - 每帧建池次数由约 10 次降到 1 次

## 5. 实现要点（踩过的坑）

### 5.1 切换职业（本机 Dalamud 15 实测）

```csharp
using FFXIVClientStructs.FFXIV.Client.UI.Misc;   // ← 命名空间很反直觉

var module = RaptureGearsetModule.Instance();
int  current = module->CurrentGearsetIndex;
int  count   = module->NumGearsets;
bool valid   = module->IsValidGearset(i);
var  entry   = module->GetGearset(i);            // GearsetEntry*
int  ret     = module->EquipGearset(i);          // 参数 int，返回 int（0 = 已提交切换）
```

- `RaptureGearsetModule` 在 **`Client.UI.Misc`**，不在 `Client.UI` 也不在 `Client.Game`。
- `EquipGearset` 参数是 `int`、返回 `int`（不是 `bool`，也**不能直接丢进字符串插值**）；
  本机还存在一个吃 `Span<byte>` 的重载，不要误用。
- `AgentGearSet` 上没有 `GetGearset`/`EquipGearset`，别往那里找。
- **游戏没有"直接切到某职业"的接口**，只能按套装切。所以前提是你已为想玩的职业保存了套装。

### 5.2 职能判定：用显式 ID 表（两次踩坑后的结论）

这一节记两次失败，供以后参考。

**第一版（错）**：拿"某一职能的字段集合"去匹配分类行，例如用
`c.GLA || c.MRD || c.PLD || ...` 判坦克。问题是游戏里每个职业可以对应它自己那一行
`ClassJobCategory`（只置该职业自己的字段），整个职能的字段集合就落空，判错。

**第二版（也错）**：改成读"该职业所属分类行的名字"。结果实测输出里**防护职业混进 19 个职业、
治疗职业混进 11 个**——说明 `sheet.GetRow(rowRef.RowId)` 取到的**不是**该职业真正的职能行
（Lumina 的 `RowRef` 解引用与按 RowId 取行在这里不等价）。因为沙箱内跑不了游戏无法继续比对，
这条路放弃了。

**现在的做法**：职能用**显式 ID 表**（`JobCatalog.RoleTable`），依据是实测输出与游戏角色面板
的职能分组；职业名和缩写仍从游戏数据读，保证国服译名正确。

| 职能 | 职业（ID） |
| --- | --- |
| 防护职业 | 骑士 19、战士 21、暗黑骑士 32、绝枪战士 37 |
| 治疗职业 | 白魔法师 24、学者 28、占星术士 33、贤者 40 |
| 近战职业 | 武僧 20、龙骑士 22、忍者 30、武士 34、钐镰客 39、蝰蛇剑士 41 |
| 远程物理职业 | 吟游诗人 23、机工士 31、舞者 38 |
| 远程魔法职业 | 黑魔法师 25、召唤师 27、赤魔法师 35、绘灵法师 42 |
| 特殊（限定） | 青魔法师 36（远程魔法）、驯兽师 43（近战） |
| 基础职业 | 剑术师 1、格斗家 2、斧术师 3、枪术师 4、弓箭手 5、幻术师 6、咒术师 7、秘术师 26、双剑师 29 |
| 能工巧匠 | 8–15 |
| 大地使者 | 16–18 |

安全网：ID 表查不到时，再按**中文名关键词**兜底判一次（新职业只要名字能匹配就不会掉出池子），
仍然判不出的会记进日志告警，不会被静默塞进某个职能。

**已知待确认**：`驯兽师` 的 ID 我填的是 43（按 ID 序列推断）。`/rcp debug` 会打印每个职业的
ID，如果驯兽师显示 `id43` 且落在近战职业，就说明对了。

**插件每次加载时都会自动把读到的套装写入日志**（不必手动执行指令）：

```
[RandomClassPicker] ===== 套装快照: 共读到 14 个 =====
[RandomClassPicker]   套装[3] 职业=钐镰客(id39,近战职业) 名称「RPR」品级=783 在池 [当前]
```

排查"某个职业明明有套装却没进随机池"时这几行就是第一手证据：能看到该套装是否被读到、
职业 ID 与职能判定、品级、以及该职业是否在设置里勾选。

### 5.4 套装编号是稀疏的，别拿数量当循环上界

**踩过的大坑**：一开始用 `module->NumGearsets` 作遍历上界：

```csharp
for (var i = 0; i < module->NumGearsets; i++)   // ✗ 会漏套装
```

玩家删过套装后，编号会出现空洞（实测该玩家的套装编号是 0-34、36、38…），
而"最高已用索引"并不等于 `NumGearsets`，结果**编号偏大的套装被整段漏掉**
（表现为"蝰蛇剑士明明有套装却提示无可用套装"）。

正确做法是扫描全部槽位，用有效性判断来过滤：

```csharp
for (var i = 0; i < MaxGearsetSlots; i++)        // ✓ 扫满槽位
{
    if (!module->IsValidGearset(i)) continue;    // 空槽位在这里被过滤
    ...
}
```

加载时的日志会同时打印 `module->NumGearsets` 与实际读到的数量、最高编号，
便于日后发现槽位语义变化。

### 5.3 窗口必须注册到绘制管线（踩过的大坑）

继承 `Dalamud.Interface.Windowing.Window` **只得到一个"可以画的窗口对象"，
它不会自己出现在屏幕上**。必须把它交给一个 `WindowSystem` 并挂到 `UiBuilder.Draw`：

```csharp
this.window = new MainWindow(this);
this.windowSystem = new WindowSystem("RandomClassPicker");
this.windowSystem.AddWindow(this.window);
PluginInterface.UiBuilder.Draw += this.windowSystem.Draw;   // ← 少这一行就永远画不出来
// Dispose 里对应地 -=、RemoveAllWindows()
```

漏掉注册的典型症状：**插件在列表里能启用、聊天指令全部正常，但界面毫无反应**，
无论 `/xxx`、点插件名还是点齿轮都一样——因为 `IsOpen` 怎么切都没有人读它。
（本插件第一版就犯了这个错，已修复。）

另外 `Window.Toggle()` 是基于 `IsOpen` 取反的，而 `Window` 的 `IsOpen` **默认为 `true`**，
所以"用命令打开窗口"应该写 `IsOpen = true` 而不是 `Toggle()`，否则第一条命令反而会把它关掉。

### 5.8 线程模型

- 抽签要发 HTTP 请求，**必须在后台线程**（`Task.Run`），否则卡住整个游戏。
- 所有游戏内存/状态读取**必须在主线程**，通过 `Framework.RunOnTick(...)` 派回去。
- 结果只写字段，`Draw()` 只读字段，不跨线程直接碰 ImGui。
- 读游戏内存的入口都包了 try/catch，未进游戏时界面不会崩。

### 5.5 同一职业的多个套装：取品级最高的（重要）

游戏对"装备缺件的套装"会直接拒绝切换，并在屏幕上弹红字：

```
无法更改套装"暗黑骑士博兹雅"的装备配置，缺少必要的装备。
```

这类套装通常是博兹雅/绝境战那种换过装备的旧套装。**没法在 API 层提前识别它**：

- `GearsetEntry` 上**没有** `IsValid` / `MissingItems` 之类的有效性标记（已逐个探测确认）。
- `EquipGearset` 是异步的——调用时返回 0（表示已提交），游戏在后续才校验装备并弹错误，
  所以**返回值不能用来判断最终是否切换成功**。

因此采用的策略是：**同一职业有多个套装时，只把装备品级最高的那个放进随机池**
（设置里「同职业只取品级最高的套装」，默认开启）。品级相同时优先保留当前正在使用的那套，
再按套装索引稳定排序保证结果可复现。这样通常就会选中你正在用的完整套装，避开旧套装。

如果同职业有两个品级相同的套装、而其中一个缺件，这招就挡不住。此时可以：
在「套装 / 历史」标签页看清楚每个套装的品级与是否在池中，手动删掉那个旧套装即可（游戏内套装列表可删）。

### 5.6 两套数字口径必须分清（曾造成"分类不对"的误判）

界面上和 `/rcp debug` 里都出现过"职能(N)"这样的数字，但 N 的**含义不同**，
一度被误认为职能分类错误：

| 数字 | 含义 |
| --- | --- |
| 职业池分组标题 `防护职业（共 6 职业 / 可用 4 职业 · 4 套装）` | 前者是**游戏里该职能有多少职业**（含基础职业），后者是**当前设置下真正能抽的** |
| 职能抽签按钮 `坦克 (4/4)` | **该职能下可用职业数 / 可用套装数** |

例如防护职业固定是 6 个（骑士、战士、暗黑骑士、绝枪战士 + 剑术师、斧术师），
但你只有其中 4 个存了套装，可用数就是 4。

现在按钮、分组标题、`/rcp debug` 三处**共用同一个 `RoleStats()` 实现**，口径不可能再分叉。

另外注意「抽到当前套装就重抽」这条：它只排除**你正在穿的那一套**，同职业的其它套装仍可被抽中。
而且这个排除**不计入界面上的"可用数量"**——当前套装本身是可用的，只是抽签时被主动跳过，
否则会出现"穿着近战套装时近战显示 5 而不是 6"这种困惑。抽签页会明确提示当前套装将被跳过。

### 5.7 GearsetEntry 的两个字段坑

读套装信息时踩到两个坑，都很隐蔽：

```csharp
// ✗ 错：Name 是 Span<byte>（UTF-8 原始字节，非 0 结尾），ToString() 只给类型名
var bad = entry->Name.ToString();          // => "System.Span<Byte>[48]"

// ✓ 对：显式按 UTF-8 解码（必要时先截到第一个 0 字节）
var span = entry->Name;
var end = span.IndexOf((byte)0);
var name = Encoding.UTF8.GetString(end >= 0 ? span[..end] : span);
```

- **`Name` 是 `Span<byte>`**，不是字符串。直接 `ToString()` 会把 `System.Span<Byte>[48]` 写进历史记录。
- **`ItemLevel` 是 `short`，读到的 790 是正确的**——当前版本满级品级就在 790 左右，
  一度被我误判成"读到垃圾值"，其实品级没问题。界面文案里的"品级 100"是过时说法，
  筛选门槛固定 100（滤掉旧套装，且不会误伤现役套装）。

### 5.9 每日随机任务：客户端 API

读取完成状态与发起排队用到的是客户端自身的能力（与游戏界面同源，不是模拟鼠标点击）：

```csharp
using FFXIVClientStructs.FFXIV.Client.Game.UI;

// 1) 完成状态：0 = 未完成
var incomplete = InstanceContent.Instance()->IsRouletteIncomplete(rouletteId);

// 2) 发起排队
var finder = ContentsFinder.Instance();
var queue  = finder->GetQueueInfo();      // ContentsFinderQueueInfo*
queue->QueueRoulette(rouletteId);         // 等价于在任务搜索器里选该随机任务并确认
```

几个踩过的坑：

- `ContentsFinder` 在 **`FFXIVClientStructs.FFXIV.Client.Game.UI`**（不在 `Client.UI.Misc`，也没有 `ContentsFinder.Instance()` 之外的同名类型）。
- `QueueRoulette` / `QueueDuties` 挂在 `ContentsFinderQueueInfo` 上，必须先经 `ContentsFinder.Instance()->GetQueueInfo()` 拿到，它本身没有静态 `Instance()`。
- **`ContentsFinderQueueState` 枚举在编译期解析不到**（命名空间层级和 `ContentsFinderQueueInfo.` 嵌套层级都试过），所以队列状态改用数值判断（`None = 0`）。
- `AtkUnitBase` 上**没有** `WindowWidth/WindowHeight`（那两个属于 `GameWindow`），窗口尺寸要取 `RootNode->Width/Height` 再乘 `Scale`。
- `AgentContentsFinder` 只有 `Show()` 可用，没有 `OpenContentsFinder()` / `OpenDutyFinder()`。

### 5.10 叠加绘制而不是改 ATK 节点

同类的 DailyDuty 走的是**直接改原生 ATK 节点**（`GetNodeById(56)`、`UpdateCollisionNodeList`），
那样能真正把复选框插进游戏列表里，但一旦节点索引随版本变化就会出问题，且很难做降级。

本插件选择**订阅 `UiBuilder.Draw` 自绘一层 ImGui 面板**贴在任务搜索器窗口上：
不改游戏节点、出问题能一键关掉、布局自己说了算。代价是位置是固定的（贴在窗口右侧），
不能像原生控件那样跟随列表滚动。

### 5.11 random.org 接口

```
https://www.random.org/integers/?num=1&min=1&max=N&col=1&base=10&format=plain&rnd=new
```

超额时可能返回 **HTTP 503 / 429**，或 **HTTP 200 但正文是 `Error: ...`**。三种都处理了：
只接受"落在目标区间内的整数"，其它一律视为失败。请求带了 `User-Agent`（random.org 的要求）。

## 6. 已知限制 / 需要你确认的点

开发沙箱里**对外 HTTPS 被完全阻断**（连 github.com 都不通），因此：

- random.org 的**实际响应格式没能联网实测**。解析写成"提取第一个落在 `[min,max]` 区间内的整数"，
  同时兼容纯数字与 HTML 错误页。第一次使用时请点界面里的**「测试 random.org 连接」**确认。
  你的游戏进程本身不受沙箱网络限制，正常情况下可用。
- `EquipGearset` 返回值语义（`0` = 成功）按签名推断，另加了"当前套装索引是否真的变了"二次确认。
  若出现"切换成功却提示失败"，放宽 `Plugin.TrySwitchTo` 里的判断即可。
- 战斗中/过场中游戏本身会拒绝切职业，这是客户端行为。
